## Problem Statement

Разработчик, ежедневно работающий с AI-агентами (Claude Code + N MCP-серверов), страдает от permission fatigue: клиент дёргает промптами allow/deny, юзер жмёт «allow не глядя» и скатывается в YOLO-режим. В этом состоянии контроля нет: ни памяти о действиях агента, ни границ. Zastava — single-binary MCP-гейтвей, переносящий approval с момента вызова на момент декларации: правила пишутся один раз, живут между сессиями, каждый вызов логируется.

Рефрейм сессии: продукт продаёт **тишину** (меньше прерываний); безопасность — побочный эффект того, что впервые стало выгодно описать свои правила.

**Перецеливание по спайку (19.08, факт):** tool-level тишина уже бесплатна в клиенте — обычный `permissions.allow` гасит промпты без Заставы, включая per-tool гранулярность, и работает даже через прокси. Ценность Заставы — то, что клиентским текстовым файлом НЕ воспроизводится: **аргументная гранулярность** (правила клиента не матчат аргументы: «github — можно, но только repo X»), **аудит-лог вызовов**, **`learn`** (правила из наблюдений) и **переносимость политик между клиентами**. Тишина остаётся приятным следствием агрегации, но не продающим тезисом.

**Границы адресуемой проблемы (честно):** Застава видит только MCP-вызовы. Промпты Bash/Edit/Write/WebFetch она не трогает в принципе. Какую долю permission fatigue составляют MCP-промпты — неизвестно; это второй обязательный артефакт spike.

## Demand Evidence

Честно: **прямых доказательств спроса нет** (вербатим: «Пока никакого — гипотеза из ресёрча»). Косвенные сигналы рынка (не спрос): ниша раздроблена — 6+ гейтвеев по 9–124★ без лидера (GitHub API, 19.08.2026); волна интереса к безопасности агентов после OpenClaw (347k★).

## Status Quo

Вербатим (Q2): «Встроенные пермишены клиента» + «Жму allow не глядя / YOLO-режим». Главный конкурент — **кнопка allow**: встроенные пермишены Claude Code бесплатны и уже работают. Их цена: промпты per-клиент и per-сессия, нет аудита, нет переносимости политик, ничего для headless/CI.

## Target User & Narrowest Wedge

**Юзер MVP:** сам автор (Q3: «Я сам — других назвать не могу») — соло-дев с Claude Code и пачкой MCP-серверов.

**Клин:** агрегирующий stdio-прокси, который (а) схлопывает N серверов в один endpoint — одно разрешение на заставу в клиенте гасит промпты всех downstream-инструментов, гранулярность переезжает в гейтвей; (б) tool-level гейтинг делегирует клиентскому allowlist (спайк: работает через прокси per-tool), а собственный enforcement включает там, где клиент бессилен — аргументные матчеры (M3); до M3 политика Заставы живёт в warn/observe; (в) логирует вызовы и считает суррогат северной метрики.

## Измерение (методика — зафиксирована до кода)

- **Северная метрика:** **суммарные прерывания/день** = MCP-промпты клиента + deny Заставы + правки конфига (метрика только «промптов/день» авто-проходит от самого факта агрегации и меряет одну сторону баланса — находка outside voice). Прямой источник — парсер session-транскриптов Claude Code (`~/.claude/projects/**/*.jsonl`), не сам гейтвей (он стоит ЗА промптом); опознаваемость промпта в транскриптах проверяется артефактом №0 spike. `zastava stats` даёт **суррогат**: уникальные сигнатуры = «сколько промптов было бы».
- **Формат лога** (разблокирует learn и M/N): `server, tool, canonical_subset` **в открытом виде** (по построению низкокардинальный и без секретов), `full_args_hash`, decision, duration. Полные аргументы — только `--log-args` (off by default).
- **Baseline:** 5 дней сбора ДО подключения заставы, разбивка промптов MCP / не-MCP.
- **Сигнатура вызова** (для M/N, learn и allowlist): `(downstream_server, tool_name, canonical_subset(args))`, где canonical_subset задан per-tool; дефолт — `{}` (tool-level). Примеры: `(github, create_issue, {repo})` — title игнорируется; `(filesystem, read_file, {path: первые 2 компонента})`; `(shotik, take_screenshot, {})`; `(qdrant, search, {collection})`. Один и тот же лог не должен давать противоположные вердикты — правила канонизации версионируются вместе с конфигом. Текстовая форма правила в конфиге — `<server>__<tool>` (совпадает с неймспейсингом; wildcard — `<server>__*`); кортеж выше — её каноническое представление.

## Constraints

- Первый Rust-проект автора: буфер времени ×1.5 к оценкам ниже.
- Разработка на Windows (npx-серверы: `cmd /c`, kill process tree, stdio-пайпы — риски M1), прод-замеры на Linux мини-ПК → CI win+linux с M0; macOS — build-only, untested (мака нет).
- rmcp pre-1.0 → пин версии; ранняя проверка server+client-role в одном процессе.
- Соло, вечерами; каждый milestone оставляет работающий инструмент.

## Premises (приняты основателем)

1. **(пересмотрена после cross-model challenge)** Юзер MVP — автор, dogfood с первого дня, **НО** валидация только по измеримым критериям (см. Success Criteria: счётчики из транскриптов, аннотации срабатываний в момент события, порог wildcard-покрытия) + второй живой юзер с отличающимся конфигом внутри MVP-окна (= v0.1.0 + 4 недели; поиск начинается с M2, а не с релиза). Субъективное «мне удобно» — не доказательство.
2. Главный конкурент — кнопка allow; после настройки промптов должно стать меньше, чем без Заставы, иначе её выключат через неделю.
3. Коммерция — гипотеза, проверяется ПОСЛЕ MVP реальными сигналами. Портфолио-ценность не зависит от исхода.
4. Дистрибуция входит в MVP: GitHub Release (Win/Linux бинари tested + macOS build-only untested), crates.io, quickstart для Claude Code.

## Cross-Model Perspective

Независимый Claude-субагент (Opus, холодное чтение):

- **Стилмен:** Застава — перенос approval'а с вызова на декларацию; рычаг — агрегация делает её одним сервером для клиента. «Продаёт не безопасность, а тишину».
- **Ключевой ответ:** «Жму allow не глядя» переопределяет продукт из security в устранитель прерываний; `zastava learn` (правила из лога) важнее ручного YAML.
- **Оспоренная премисса:** dogfood N=1 без метрик неотличим от самообмана → фальсифицируемые критерии внесены в премиссу 1.
- **48ч-прототип:** spike прежде всего; M/N — потолок ценности идеи.

Второй независимый ревьюер (спек-ревью, 19 находок) добавил: адресуемая доля MCP-промптов неизвестна (→ артефакт spike), окно M1–M2 без enforcement хуже статус-кво (→ allowlist-гейт с M1), сигнатура должна быть зафиксирована до spike (→ секция «Измерение»), полное логирование аргументов до маскировки — утечка (→ args_hash по умолчанию с M1).

## Approaches Considered

- **A «Слушающая застава»** (прокси+лог, политики потом) — отклонён как **конечное состояние**; его порядок принят внутри C с зафиксированными обязательствами M3/M4.
- **B «Крепость по плану»** (исходный inc-1 как есть) — отклонён: 4 milestone'а инфраструктуры вокруг непроверенной гипотезы, о провале узнаём через месяцы.

## Recommended Approach

**C «Гибрид»: validation-first порядок внутри портфолио-архитектуры** (workspace 3 крейта core/proxy/cli, zero unsafe, тесты, CI с M0). Оценки — вечерами, до буфера ×1.5:

- **Spike (gate ДО M0, 1–2 вечера, строго на rmcp — заодно убивает главный техриск server+client в одном процессе).** Артефакт №0: grep транскриптов на заведомо случившийся промпт (опознаваем ли он вообще — 30 мин). **Контрольное плечо** (главная находка outside voice): три конфигурации — статус-кво / `permissions.allow` на серверы БЕЗ Заставы / через Заставу (2 фиктивных префиксованных downstream; синтаксис правила по актуальной доке). Ветвление: Застава не гасит промпты → STOP, перецеливание; **allow-без-Заставы ≈ Застава → tool-level тишина уже бесплатна в клиенте, перецеливаем позиционирование на «аргументная гранулярность + аудит + learn + переносимость»**; MCP-доля baseline < ~20% → пересмотр метрики. Baseline 5 дней. Параллельно: placeholder на crates.io.
- **M0 (2–3 вечера).** Workspace, CI win+linux (+macOS build-only), clap-каркас, парсинг конфига **fail-closed**: не парсится → отказ старта с громкой ошибкой.
- **M1 (~1 неделя).** Прокси для одного сервера, **неймспейсинг `<server>__<tool>` всегда, с первого дня** (иначе апгрейд M1→M2 ломает allowlist юзера). JSONL-лог: по умолчанию `tool + args_hash + размер` (полные аргументы — только `--log-args`, off by default; секреты не пишутся на диск до появления маскировки). **Минимальный allowlist-гейт**: первый прогон — observe/warn (гейт ещё пуст), по его логу генерится стартовый tool-level allowlist, затем включается enforce — окно «YOLO+лог» ограничено одним bootstrap-прогоном, а не milestone'ами. Минимальный `zastava allow <sig>` + file-watch reload — цикл deny→allow→retry без рестарта с первого дня (решение eng-review T3); `zastava import` из .claude.json. `zastava stats` + парсер транскриптов (baseline/после). Windows-подзадача: spawn через `cmd /c`, kill-tree, тест на зависший дочерний процесс.
- **Порядок пересобран (T5): M2-lite → M3 → M2-full** («learn важнее ручного YAML» — собственный вывод этого дока). M2-lite: 2–3 реальных сервера работают без полной conformance-матрицы; M3 — дифференциатор; M2-full — харднинг перед релизом:
- **M2-full (перед M4).** Агрегация N: request-id remapping между соединениями, merge initialize-capabilities, проброс list_changed / cancellation / progress, коллизии и лимит длины имён (в ряде клиентов 64 симв.), per-server fail-closed (downstream умер → его tools исчезают из списка, вызов даёт ошибку). Mock downstream + conformance-тесты, включая «умер посреди запроса» — здесь, не в M4. Публикация WIP-репо + начало поиска второго юзера.
- **M3 (~1.5 недели).** Политики v2: матчеры аргументов по канонической сигнатуре, `zastava learn` (черновики allow-правил из лога, юзер вычёркивает), `zastava annotate <event-id>` (фиксация полезности срабатывания в момент события). Deny — структурированная ошибка модели: «denied by zastava rule X; run `zastava allow <sig>` to permit» + запись в лог + опциональная desktop-нотификация (модель молча ищет обходные пути — юзер должен узнавать о срабатываниях не из чата). Новые аргументные правила M3 первую неделю живут в warn-mode (лог без блокировки), enforce включается флагом; tool-level гейт M1 всё это время остаётся в enforce.
- **M4 (~1 неделя).** Полноценная маскировка секретов в ответах, criterion-бенчи + overhead p50/p99 на мини-ПК, README (quickstart, цифры, гиф с ≥2 серверами), GitHub Release, crates.io publish.
- **MVP-окно = v0.1.0 + 4 недели:** замер Success Criteria, второй юзер.

## Config & Invocation

Конфиг: TOML. Путь: `%APPDATA%\zastava\zastava.toml` (Windows) / `~/.config/zastava/zastava.toml` (Linux/macOS); лог и данные рядом (`%LOCALAPPDATA%` / `~/.local/share/zastava/`). Downstream-серверы объявляются как в клиентах (command/args/env/cwd; url-транспорт — вне v0.1). Эскиз:

```toml
[servers.github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]

[servers.shotik]
command = "node"
args = ["C:/path/to/shotik/mcp/index.js"]

[policy]
mode = "enforce"        # warn | enforce
default = "deny"

[[policy.allow]]
sig = "github__*"         # tool-level; аргументные матчеры — M3
```

Подключение в Claude Code (`.claude.json` / `claude mcp add`) — «три строчки» из Distribution Plan:

```json
{ "mcpServers": { "zastava": { "command": "zastava", "args": ["run"] } } }
```

## Non-goals / Later (за пределами v0.1.0)

- **Hash-chain + `zastava audit verify`** → v0.2: tamper-evident журнал — enterprise-фича, у соло-дева нет threat model «кто-то с доступом к моей машине подделывает мою историю»; append-only JSONL достаточно. Остаётся в роадмапе как портфолио-фича v0.2.
- Streamable HTTP на клиентской стороне, elicitation-confirm, дашборд/TUI, SQLite (триггер пересмотра: >100k событий/мес или потребность в ad-hoc запросах).

## Success Criteria

- **Spike:** промпты гасятся одним разрешением; MCP-доля baseline задокументирована (≥ ~20%, иначе пересмотр).
- **2 недели dogfood (пост-спайк критерии ценности):** 100% MCP-вызовов в аудит-логе (мульти-инстанс не бьёт лог); ≥1–2 полезных срабатывания **аргументных** правил/неделю, аннотированных `zastava annotate` в момент события (ретро не засчитывается); ≥50% черновиков `learn` принимается без ручной правки (learn acceptance rate); переносимость: один zastava.toml работает минимум в двух клиентах (Claude Code + Cursor/Desktop, TODO-1). Промпты/день из baseline-хука — информационно.
- **M/N ≥ ~50%** по зафиксированной сигнатуре (доля вызовов, повторяющих одобренные сигнатуры) — иначе policy-once не побеждает кнопку allow даже теоретически.
- **v0.1.0:** CI зелёный (fmt, clippy -D warnings, тесты, win+linux), zero unsafe, README с бенчами с мини-ПК, Release + crates.io, гиф: Claude Code через заставу с ≥2 серверами.
- **Второй юзер** с отличающимся конфигом — **stretch-цель, не гейт** (T7): валидация держится на измеримых метриках выше. Каналы зафиксированы: r/rust + MCP-дискорд (пост с гифкой после M3), личные DM 5 конкретным людям, круг заказчиков по автоматизациям.
