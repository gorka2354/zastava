## Ручная часть: три плеча

В каждой папке `testbed/arm-*` запусти `claude`, дай агенту задание:
«вызови tools alpha ping и beta ping с сообщением test, каждый по два раза»
— и запиши, сколько permission-промптов ты увидел и как они выглядели.

| Плечо | Что настроено | Записать |
|---|---|---|
| **arm-a** (статус-кво) | alpha+beta напрямую, БЕЗ permissions | промптов на 4 вызова: ___ |
| **arm-b** (контроль!) | alpha+beta напрямую + `permissions.allow: ["mcp__alpha","mcp__beta"]` | промптов: ___ |
| **arm-c** (Застава) | только proxy + `allow: ["mcp__zastava"]` | промптов: ___ |

Дополнительно в arm-b: проверь гранулярный синтаксис — замени allow на
`["mcp__alpha__ping"]` (tool-level) и посмотри, гасит ли он промпт только этого тула.
Это отвечает на вопрос «может ли клиент гейтить per-tool через префикс сам».

## Интерпретация (ветвление из плана §5)

- **arm-c промптит** → механика тишины мертва → STOP, перецеливание (аудит/learn-продукт).
- **arm-b ≈ arm-c** (оба тихие) → tool-level тишина бесплатна в клиенте → перецеливание
  позиционирования на «аргументная гранулярность + аудит + learn + переносимость»;
  activируется TODO «learn без прокси».
- **arm-b промптит, arm-c нет** → клин «агрегация = тишина» подтверждён → план как есть.

## Baseline-хук (5 дней, до подключения Заставы)

Хук-счётчик permission-промптов: `spike/baseline-hook.ps1` пишет строку в
`~/.zastava/baseline.jsonl` на каждый промпт. Установка — секция hooks в
`~/.claude/settings.json` (см. README-сниппет в этом файле ниже) — ставится
только с твоего согласия, снимается удалением секции.

```json
"hooks": {
  "Notification": [
    {
      "matcher": "permission_prompt",
      "hooks": [
        { "type": "command", "command": "powershell -NoProfile -ExecutionPolicy Bypass -File C:/path/to/zastava/spike/baseline-hook.ps1" }
      ]
    }
  ]
}
```

Через 5 дней: `zastava`-репо, `python spike/baseline-report.py` (появится в M1;
пока достаточно `wc -l ~/.zastava/baseline.jsonl` в день).
